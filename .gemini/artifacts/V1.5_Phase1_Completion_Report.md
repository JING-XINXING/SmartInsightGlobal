## 💡 最佳实践总结

### 1. i18n 架构
- **命名空间分离**: 使用 common, auth, dashboard, reports, settings 分离翻译
- **跨命名空间引用**: 使用 `t('namespace:key')` 语法
- **类型安全**: TypeScript 确保翻译键正确性

### 2. 组件内 Schema
- **动态验证**: 在组件内部定义 Zod schema 以使用 `t()` 函数
- **避免全局 schema**: 全局 schema 无法访问 i18n 上下文

### 3. 日期本地化
- **动态 locale**: 根据 `i18n.language` 动态选择 date-fns locale
- **一致性**: 所有日期显示使用相同的本地化方式

### 4. Toast 消息
- **统一翻译**: 所有 toast 消息使用 i18n
- **命名空间**: 通用消息使用 common 命名空间

## 🎓 经验教训

### 成功经验
1. **渐进式迁移**: 逐页更新，每次更新后立即测试
2. **构建验证**: 每次更改后运行构建确保无错误
3. **命名空间组织**: 合理的命名空间使翻译管理更清晰
4. **类型安全**: TypeScript 帮助发现翻译键错误

### 遇到的问题
1. **Zod Schema 位置**: 需要将 schema 移到组件内部才能使用 `t()`
   - 解决: 在组件内部定义 schema

2. **日期格式**: 需要根据语言动态选择 locale
   - 解决: 使用 `i18n.language` 判断并选择对应 locale

3. **命名空间语法**: 跨命名空间引用需要特殊语法
   - 解决: 使用 `t('namespace:key')` 或 `t('key', { ns: 'namespace' })`
